## 1. 项目背景与目标

### 1.1 背景
家里孩子就读小学四年级，语文教材为人民教育出版社四年级上册。家长希望把课本知识变成"闯关游戏"，让孩子每天主动学习约 20 分钟，通过即时反馈与积分奖励培养学习兴趣，并通过积分兑换奖品形成正向激励。

### 1.2 目标
1. 交付一套**三端全部真实运行、联调通过**的全栈应用：
   - **H5 用户端**：孩子答题闯关（平板为主）
   - **管理后台 Admin**：家长配置奖品、题量、查看统计
   - **后端 API**：Spring Boot + MySQL
2. 题目内容严格来自课本（课内知识点 + 语文园地"日积月累"）。
3. 建立"答题得积分 → 积分兑换奖品"的闭环奖惩机制。
4. 最终部署到 192.168.110.99，家长可实测。

### 1.3 非目标（本期不做）
- 不做在线支付、不做物流对接（奖品兑换为线下发放，后台标记状态）
- 不做多学校/多班级、不做社交排行（可后续迭代）
- 不做题目 AI 自动生成（题库人工编写并入库）
- 不做小程序端

## 3. 核心业务流程

### 3.1 孩子端主流程
```
选择/创建孩子档案 → 输入 4 位 PIN → 科目选择（语文 / 数学，v2.0 新增）
   → 进入对应科目的闯关地图 → 选择已解锁的关卡 → 逐题作答
   → 提交本关 → 结算（正确率 / 星级 / 获得积分）
   → 达标则解锁下一关 → 可去积分商城兑换奖品
```

> **v2.0 科目规则**：两科共用同一套孩子档案、积分、奖品；**每日限额每科各一套**（语文、数学各自 20 题/天、20 分钟/天，分别计算、分别拦截，2026-09-25 家长确认）；两科闯关地图与进度**互相独立**。积分商城、积分流水不区分科目。

### 3.2 家长端主流程
```
账号密码登录 → 仪表盘查看概览 → 维护题库 / 配置规则 / 维护奖品
   → 审核孩子提交的兑换申请 → 线下发放并标记"已发放"
```

### 3.3 奖惩机制（可后台配置）
**奖励**
- 每答对 1 题：+`pointsPerCorrect` 分（默认 10）
- 连对加成：每连对 3 题额外 +`comboBonus` 分（默认 5），可关闭
- 通关奖励：每通关 1 个关卡额外 +`pointsPerLevelPass` 分（默认 20）
- 三星通关额外奖励：+`pointsPerThreeStar`（默认 30）

**约束（防止过度游玩）**
- 每日答题数量上限：`dailyQuestionLimit`（默认 20 题/天，家长可调）
- 每日游玩时长上限：`dailyMinuteLimit`（默认 20 分钟/天，家长可调）
- 超出上限后当天不可再开始新关卡，提示"今天学得很棒，明天再来吧！"

**"惩罚"设计原则：以正向激励为主，不做重罚**
- 答错不扣积分（避免挫败感）
- 答错影响本关星级与是否通关（间接后果）
- 星级评定（正确率）：
  - 三星：正确率 ≥ 90%
  - 二星：正确率 ≥ 70%
  - 一星：正确率 ≥ 60%
  - 未达 60%：不通关、不获通关奖励，可无限重试（不消耗每日题量额度以外的资源）

## 5. 关卡设计

- 每篇课文划分为若干**关卡**，每关题目数由后台配置 `questionsPerLevel`（默认 5 题/关）
- 关卡命名：`第1关`、`第2关`…，可由后台改为自定义名称（如"观潮·初探"）
- **解锁规则**：线性推进。单元内课文逐课解锁；课文内关卡逐关解锁；上一单元全部通关后才解锁下一单元
- 每关记录：状态（未解锁/已解锁/已通关）、最好星级、最高分、尝试次数
- 未通关的关卡可重复挑战，**只有首次通关才发放通关奖励积分**
- **家长重置进度（F-AD-06）语义**：重置某关后，该关回到「已解锁」，星级与尝试次数清零，可重新挑战并再次获得通关奖励；**不影响其后关卡已获得的「已通关」状态与其星级**。重置全部进度则全部关卡回到初始状态（仅第 1 关解锁）
