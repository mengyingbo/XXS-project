## 1. H5 端电影片库（F-H5-14 · v3.0 · 阶段 14）

### 1.1 功能概述

| 项目 | 内容 |
|------|------|
| 编号 | F-H5-14 |
| 路由 | `/movies` |
| 组件 | `MovieLibrary.vue`（新增） |

### 1.2 页面结构

1. **顶部导航栏**：‹ 返回 + "🎬 电影片库"标题 + 副标题
2. **统计概览栏**（四列等宽）：
   - 总片数（50）
   - 已看（27，绿色）
   - 未看（23，橙色）
   - 平均分（8.8）
3. **筛选标签**（三个按钮）：全部 / 已看 / 未看
4. **搜索框**：支持按电影名、类型、推荐主题、适龄看点搜索
5. **电影网格**：
   - 响应式网格（min 155px 自适应列数）
   - 每张卡片：封面图（2:3 竖版比例）+ 左上角评分角标（★ 豆瓣评分）+ 右下角观看状态角标（✓ 已看 / 未看）
   - 卡片底部：电影名 + 类型·片长
   - 已看电影卡片有绿色边框高亮
6. **电影详情弹窗**（点击卡片弹出）：
   - 封面图（160×240）
   - 电影标题
   - 四个标签：类型（蓝）/ 片长（灰）/ 评分（金）/ 观看状态（绿已看/橙未看）
   - 推荐主题
   - 适龄看点
   - 操作按钮：关闭 + 标记为已看/未看

### 1.3 数据结构

```typescript
interface Movie {
  no: number          // 序号 1-50
  name: string        // 电影名称
  type: string        // 类型（如"成长/音乐"）
  duration: number    // 片长（分钟）
  rating: number      // 豆瓣评分
  theme: string       // 推荐主题（如"包容与赏识"）
  note: string        // 适龄看点（如"用合唱唤醒问题学生，比说教更动人"）
  watched: boolean    // 观看状态（已看/未看）
  cover: string       // 封面图路径
}
```

### 1.4 观看状态持久化

- v3.0：`localStorage` 键名 `movie-watched-status`，按电影序号 `no` 存储
- v3.1 起：键名改为 `movie-watched-status-v2`，按数据库 `id` 存储，首次访问用接口返回的 `watched` 字段作为默认值（见 2.6.3）
- 在详情弹窗中点击"标记为已看/未看"可切换状态，即时写入 localStorage；刷新页面后状态保持

### 1.5 数据来源与封面提取

- 电影数据来自家长提供的 Excel 文件：`四年级高分电影Top50_带封面带观看状态.xlsx`
- 50 张封面图从 Excel 内嵌图片中提取，通过解析 `xl/drawings/drawing1.xml` 的锚点信息映射到对应电影行
- v3.0：封面重命名为 `cover-1.png ~ cover-50.png`，存放在 H5 `public/movie-covers/` 目录
- v3.1 起：封面迁移至后端 `/opt/xxs/uploads/`，cover 字段统一为 `/api/files/cover-N.png`（见 2.3.3）

## 2. 后台管理与 H5 改造（F-AD-12 / F-H5-15 · v3.1 · 阶段 15）

### 2.1 背景

v3.0 的电影片库（F-H5-14）是**纯前端静态实现**：50 部电影数据硬编码在 `frontend-h5/src/data/movieData.ts`，封面图放在 `frontend-h5/public/movie-covers/`，观看状态存 localStorage。家长如果想增加新电影，需要手动修改 TypeScript 源码并重新编译部署，门槛高。

本次需求：增加**后台管理功能**，家长通过管理端可视化界面增删改查电影，H5 端自动从后端 API 获取电影列表，无需改代码即可新增电影。

### 2.2 功能清单

| 编号 | 功能 | 端 | 说明 |
|------|------|----|------|
| F-AD-12 | 电影片库后台管理 | 管理端 | 电影 CRUD + 封面上传，家长可视化操作 |
| F-H5-15 | H5 电影片库改走后端 API | H5 端 | MovieLibrary 从后端 API 拉取电影列表，替代静态数据 |

### 2.3 数据库设计

#### 2.3.1 新增表 `movie`

```sql
CREATE TABLE movie (
  id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  no          INT          NOT NULL DEFAULT 0     COMMENT '显示序号（排序用）',
  name        VARCHAR(100) NOT NULL                COMMENT '电影名称',
  type        VARCHAR(50)  NOT NULL DEFAULT ''     COMMENT '类型（如"成长/音乐"）',
  duration    INT          NOT NULL DEFAULT 0      COMMENT '片长（分钟）',
  rating      DECIMAL(3,1) NOT NULL DEFAULT 0.0   COMMENT '豆瓣评分',
  theme       VARCHAR(100) NOT NULL DEFAULT ''     COMMENT '推荐主题（如"包容与赏识"）',
  note        VARCHAR(500) NOT NULL DEFAULT ''     COMMENT '适龄看点',
  cover       VARCHAR(255) NOT NULL DEFAULT ''     COMMENT '封面图URL（/movie-covers/cover-N.png 或 /api/files/xxx.png）',
  watched     TINYINT(1)   NOT NULL DEFAULT 0     COMMENT '默认观看状态（0未看/1已看），H5首次访问的初始值',
  enabled     TINYINT(1)   NOT NULL DEFAULT 1     COMMENT '是否上架（0下架/1上架），下架的电影不在H5端显示',
  sort_order  INT          NOT NULL DEFAULT 0     COMMENT '排序权重（升序），同 enabled 一起控制H5显示顺序',
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP         COMMENT '创建时间',
  updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (id),
  KEY idx_enabled_sort (enabled, sort_order, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='电影片库';
```

#### 2.3.2 数据迁移

将 `movieData.ts` 中现有 50 部电影迁移到 `movie` 表：

- 自动生成 SQL 脚本 `sql/60_movies.sql`，包含 50 条 INSERT
- `no` 字段 = 原序号 1~50
- `cover` = 原路径 `/movie-covers/cover-N.png`（封面图保留在 H5 public 目录，无需移动）
- `watched` = 原初始观看状态（27 部已看为 1，23 部未看为 0）
- `enabled` = 1（全部上架）
- `sort_order` = no（按序号排序）

#### 2.3.3 封面图策略

| 来源 | cover 字段值 | 说明 |
|------|-------------|------|
| 现有 50 部（设计时） | `/movie-covers/cover-N.png` | 保留在 H5 public 目录，Apache 直接服务 |
| 后续新增（设计时） | `/api/files/xxx.png` | 通过管理端上传到后端 uploads 目录，复用现有上传接口 |

> **实施调整（2026-10-04）**：测试发现管理端无法访问 H5 的 `/movie-covers/` 静态路径。将 50 张封面迁移到后端 `/opt/xxs/uploads/`，数据库 cover 字段统一改为 `/api/files/cover-N.png`，两端均通过后端加载封面，本地 dev 与生产环境一致。

### 2.4 后端 API 设计

#### 2.4.1 管理端接口（需 Admin Token，路径 `/api/admin/movie`）

复用现有分层模式（Entity → Mapper → Service → Controller → DTO），参考 `AdminPrizeController` / `AdminPrizeService` 的写法。

| 方法 | 路径 | 说明 | 请求参数 |
|------|------|------|---------|
| GET | `/api/admin/movie` | 分页列表 | `page`, `size`, `keyword`(可选，模糊匹配**电影名/类型/主题**，v3.3), `enabled`(可选) |
| POST | `/api/admin/movie` | 新增电影 | `MovieSaveReq`（见 2.4.3），v3.3 起同名电影查重 |
| PUT | `/api/admin/movie/{id}` | 修改电影 | `MovieSaveReq`，v3.3 起同名电影查重（排除自身） |
| PUT | `/api/admin/movie/{id}/move` | 上移/下移排序（v3.3 新增） | `dir`=`up`/`down` |
| DELETE | `/api/admin/movie/{id}` | 删除电影 | —，v3.3 起删除时顺带清理封面文件 |

#### 2.4.2 公开接口（免登录，供 H5 端获取，路径 `/api/movie`）

> 需在 `WebConfig.java` 中将 `/api/movie` 排除在 `AdminAuthInterceptor` 和 `ChildAuthInterceptor` 拦截范围之外（两个拦截器分别只拦截 `/api/admin/**` 和 `/api/child/**`，`/api/movie` 本身不被拦截，**无需改 WebConfig**）。

| 方法 | 路径 | 说明 | 返回 |
|------|------|------|------|
| GET | `/api/movie` | 已上架电影列表 | `Movie[]`（按 sort_order, id 升序，仅返回 enabled=1） |

#### 2.4.3 请求体 `MovieSaveReq`（新增到 `AdminDtos.java`）

```java
public record MovieSaveReq(
    Integer no,                                           // 显示序号
    @NotBlank(message = "电影名称不能为空")
    @Size(max = 100, message = "名称过长") String name,
    @Size(max = 50, message = "类型过长") String type,
    Integer duration,                                      // 片长（分钟）
    BigDecimal rating,                                     // 豆瓣评分
    @Size(max = 100, message = "主题过长") String theme,
    @Size(max = 500, message = "看点过长") String note,
    @Size(max = 255, message = "封面地址过长") String cover,
    Boolean watched,                                       // 默认观看状态
    Boolean enabled,                                       // 是否上架
    Integer sortOrder                                      // 排序权重
) {}
```

### 2.7 数据流总览

```
家长在管理端新增电影
  → POST /api/admin/movie（带 Admin Token）
  → AdminMovieController → AdminMovieService → MovieMapper → MySQL movie 表

孩子打开 H5 电影片库
```

## 3. 豆瓣自动检索（F-AD-13 · v3.2~v3.3 · 阶段 15）

### 3.1 背景与功能概述

v3.1 的电影管理需要家长手动填写全部字段（类型、片长、评分、主题、看点、封面），操作繁琐且容易出错。家长希望：**输入电影名称后，系统自动从网上检索电影信息并填充表单**，特别是封面图自动获取，减少手工录入。

| 项目 | 内容 |
|------|------|
| 编号 | F-AD-13 |
| 数据源 | 豆瓣电影（与现有 50 部电影的评分体系一致，中文最权威） |
| 交互 | 输入电影名 → 点击"检索" → 展示候选列表 → 家长选择 → 表单自动填充 |
| 降级 | 豆瓣不可用时提示错误，家长手动填写（现有流程不受影响） |

**已验证可行性（2026-10-04 实测）**：豆瓣搜索页 `https://www.douban.com/search?cat=1002&q={名称}` 可正常访问，返回候选列表（片名、年份、评分、海报、简介）；电影详情页可获取类型、片长等完整信息。

### 3.2 字段映射方案

| 表单字段 | 豆瓣来源 | 填充策略 |
|---------|---------|---------|
| 电影名称 | 搜索结果片名 | 自动填充 |
| 类型 | 详情页"类型"（如 剧情/音乐） | 自动填充 |
| 片长(分钟) | 详情页"片长"（如 97分钟），解析出数字 | 自动填充 |
| 豆瓣评分 | 详情页评分（如 9.3） | 自动填充 |
| 适龄看点 | 详情页剧情简介 | **预填简介，家长编辑**（豆瓣无"适龄看点"概念，简介是最接近的素材） |
| 封面图 | 详情页海报 URL | **自动下载到后端 uploads**，cover 存 `/api/files/xxx.jpg`（豆瓣外链有防盗链，不能直接引用） |
| 推荐主题 | 无直接来源（豆瓣标签格式不匹配，如"经典/教育"≠"包容与赏识"） | **留空，家长手动填写**（个性化内容，不宜机器生成） |
| 显示序号 | — | 不动 |
| 默认观看 / 上架 / 排序 | — | 不动（保持当前默认值） |

### 3.3 后端 API 设计

#### 3.3.1 检索接口（两步式，需 Admin Token）

| 方法 | 路径 | 说明 | 入参 | 返回 |
|------|------|------|------|------|
| GET | `/api/admin/movie/search` | 第一步：搜索候选列表 | `name`（电影名） | `候选数组`（最多 10 个） |
| GET | `/api/admin/movie/fetch` | 第二步：获取选中电影详情 | `url`（候选中的详情页地址） | `完整信息对象`（含已下载的封面） |

#### 3.3.2 返回结构

**搜索候选**（一个候选）：
```
{ title: "放牛班的春天", year: "2004", rating: "9.3",
  posterUrl: "https://img3.doubanio.com/...", 
  subjectUrl: "https://movie.douban.com/subject/1291549/",
  director: "克里斯托夫·巴哈蒂", actors: "让-巴蒂斯特·莫尼耶 / ..." }
```

**详情结果**（点选后返回，直接对齐表单）：
```
{ name: "放牛班的春天", type: "剧情/音乐", duration: 97,
  rating: 9.3, note: "1949年的法国乡村，音乐家克莱门特…（完整简介）",
  cover: "/api/files/ab12cd34.jpg" }  // 海报已下载入库
```

#### 3.3.3 技术实现要点

1. **HTTP 客户端**：Java 17 原生 `HttpClient`（项目已是 Spring Boot 3 / Java 17+，无需新增依赖）
2. **请求伪装**：设置浏览器 User-Agent、Accept-Language，避免被豆瓣拦截
3. **HTML 解析**：用正则解析（豆瓣搜索页与详情页结构多年稳定，搜索页的评分/海报/标题有固定 HTML 模式；不引入 Jsoup 避免增加依赖）
4. **海报下载**：`GET /api/admin/movie/fetch` 时同步下载海报到 `uploads/` 目录（复用现有上传目录配置 `xxs.upload.dir`），文件名 UUID，存路径 `/api/files/xxx.jpg`。
   **v3.3 调整**：搜索步骤（`/movie/search`）**不再预下载海报**——候选列表直接返回豆瓣原图 URL，管理端候选弹层用 `<img referrerpolicy="no-referrer">` 绕过豆瓣防盗链直连展示；只有家长点选候选调用 `/movie/fetch` 时才真正下载海报到本地。避免一次搜索白下 10 张海报产生磁盘垃圾和等待
5. **片长解析**：详情页"片长: 97分钟"，正则提取数字；多版本片长（如"97分钟 / 110分钟"）取第一个
6. **类型转换**：豆瓣详情页类型是"剧情 / 音乐"（空格+斜杠），转换为表单格式"剧情/音乐"
7. **超时控制**：搜索/详情请求超时 10 秒，海报下载超时 10 秒；豆瓣访问失败返回友好错误（code 502 + "豆瓣访问失败，请稍后重试或手动填写"）
8. **限频保护**：家庭自用场景频率低，暂不做主动限频；若豆瓣临时限流会返回错误，不影响手动填写流程

### 3.6 风险与降级

| 风险 | 概率 | 应对 |

| 豆瓣反爬限制（IP 封禁/验证码） | 低（家庭自用频率低） | 接口返回友好错误，家长手动填写，功能入口不影响 |
| 豆瓣页面结构变化 | 低（多年稳定） | 解析失败时返回"解析失败"，不影响手动流程 |
| 海报下载失败（外链失效） | 低 | 返回其他字段，封面留空，家长手动上传 |
| 豆瓣简介与"适龄看点"不完全匹配 | 必然（数据源差异） | 定位为"预填素材"，家长编辑后保存 |
