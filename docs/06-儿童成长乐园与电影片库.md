## 4. 管理端加载优化（F-AD-11）

| 项目 | 内容 |
|------|------|
| 编号 | F-AD-11 |
| 问题 | 管理端 JS 单包 1.19MB，局域网慢速连接下加载 30 秒以上 |
| 根因 | `vite.config.ts` 中 `inlineDynamicImports: true` + `manualChunks: undefined`，所有代码打成一个文件（为兼容 iOS 11 单文件限制） |
| 方案 | 管理端是家长使用，无需 iOS 11 单文件限制；改为 `manualChunks` 拆分三路 chunk |

### 4.1 拆分结果

| 文件 | 原大小 | 拆分后 | gzip 后 | 内容 |
|------|--------|--------|---------|------|
| app 代码 | 1.19MB | 82KB | 23KB | 管理后台业务代码 |
| vendor | (混在一起) | 164KB | 60KB | Vue / Router / Pinia / Axios |
| element-plus | (混在一起) | 937KB | 288KB | Element Plus + Icons |
| CSS | 365KB | 365KB | 49KB | 不变 |

### 4.2 效果

- 首屏加载：浏览器通过 `modulepreload` 并行下载三个 chunk，不再串行等一个大文件
- 后续访问：vendor 和 element-plus 被浏览器 ETag 缓存，只需重新下载 23KB app 代码
- 旧版备份为 `admin.bak-20261004`

## 5. 服务器端预压缩（部署优化）

| 项目 | 内容 |
|------|------|
| 问题 | Apache 实时 gzip 压缩在慢速连接下 CPU 开销大；USB WiFi 适配器吞吐量间歇性降到 0.2KB/s |
| 方案 | 服务器预压缩所有 `.js` / `.css` / `.png` 为 `.gz` 文件；Apache 配置 `mod_rewrite` 在浏览器支持 gzip 时直接发送预压缩文件 |
| 状态 | `.gz` 文件已生成；Apache 配置文件已上传至 `/tmp/xxs-optimized.conf`，需 sudo 执行启用（见第 6 章） |

## 6. 待执行项

> 以下操作需要 sudo 权限，家长在服务器上手动执行：

```bash
ssh mengyingbo@192.168.110.99
sudo bash -c '
a2enmod rewrite && \
cp /etc/apache2/sites-enabled/xxs.conf /etc/apache2/sites-enabled/xxs.conf.bak-$(date +%Y%m%d) && \
cp /tmp/xxs-optimized.conf /etc/apache2/sites-enabled/xxs.conf && \
apache2ctl configtest && \
systemctl reload apache2 && \
echo "=== Apache 配置更新完成 ==="
'
```

**效果**：启用 mod_rewrite → 备份旧配置 → 应用新配置（预压缩 + Cache-Control 缓存头）→ 热重载 Apache。执行后第二次打开管理端浏览器缓存命中，秒开。

## 8. 硬件建议（非项目需求，仅供参考）

> 排查发现本机使用 USB WiFi 适配器（Realtek RTL8188EU），TCP 吞吐量间歇性降到 0.2KB/s，是管理端加载慢的外部因素之一。建议更换为 Intel AX210 芯片的 PCIe 无线网卡（如 Fenvi FV-AX3000P，约 ¥150-180），可根治 USB WiFi 电源管理降速问题。此项为硬件建议，不属于项目开发范围。
