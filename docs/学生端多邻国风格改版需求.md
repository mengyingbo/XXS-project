# 学生端 H5「多邻国风格」答题闯关改版 — 需求文档

> 编写日期：2026-09-23
> 适用范围：`frontend-h5`（学生端）为主，`backend` 仅新增只读能力，`frontend-admin` 不改动
> 依据：家长提供的多邻国 App 截图 2 张（深色主题、之字形圆形节点闯关地图）
> 约束：本文档确认前不进入开发；确认后实现严格遵循本文档，不擅自增删功能。

---

## 1. 改版背景与目标

当前学生端闯关地图为「单元卡片手风琴 → 课文 → 方形小关卡按钮」的信息列表式布局，答题为整卷作答后统一反馈。本次改版将学生端改为多邻国（Duolingo）式体验：

1. **闯关地图**：纵向**之字形圆形节点路径**，一个节点 = 一关，节点沿虚线依次排列、左右摆动，当前关放大高亮并有吉祥物陪伴；课与课之间有课名分隔条，单元有橙色横幅与终点奖杯节点。
2. **答题过程**：改为**逐题「检查 → 即时对错反馈 → 继续」**节奏，底部固定大按钮与多色反馈面板，答错的题在本轮末尾自动回炉复习一遍。
3. **视觉风格**：参照截图的**深色主题 + 金/橙圆形厚边节点 + 3D 厚边按钮**，整体更卡通、更有游戏感。
4. **结算页**：全屏庆祝式结算（星级动画、积分获得、连续学习正反馈、下一关引导）。

### 1.1 明确不改变的部分（重要）

- 教材结构不变：8 单元 / 34 个教学单元（27 课 + 7 语文园地）/ 约 100 个关卡 / 480 题。
- **关卡解锁规则不变**：线性推进，前一关通关才解锁下一关；单元顺序解锁。
- **积分规则不变**：答对 +10、三连对 +5、首次通关 +20、首次三星 +30、答错不扣分（分值仍以后台配置为准）。
- **星级规则不变**：按正确率由后台阈值配置（1/2/3 星，正确率过低不通过）。
- **每日限额不变**：默认 20 题 / 20 分钟，超限拦截；5 次 PIN 错误锁定 1 分钟不变。
- 商城、兑换、我的（含错题本、积分流水、兑换记录）、家长端后台、数据库表结构均不变。
- 不改注册 / 档案选择 / PIN 登录流程，仅做视觉统一。

### 3.2 通用组件风格

- **圆形关卡节点**：直径 68px（当前关 80px），圆形 + 6px 同色厚底边（`border-bottom`/阴影模拟 3D），按下时向下位移 3px；白色粗线条 emoji 图标；节点之间用弯曲**虚线**串联。
- **大按钮**：圆角 16px，厚底边 4~6px，按下位移；最小点击区 48×48px（F-H5-11 不变）。
- **选项卡**（选择题）：大号描边卡片，选中时蓝边 `#84d8ff` + 浅蓝底；答错选中红边，正确项绿边（反馈阶段）。
- **进度条**：顶部细条，已完成部分绿色 `#58cc02`，圆角胶囊，无百分比文字时以分段式呈现。
- **字体**：沿用系统中文字体；题干 ≥20px，圆润粗体；不出现小字密排。
- 动效：当前关轻微上下浮动 + 入场弹跳；切题左右滑动；反馈面板自底部滑入；结算星级依次弹入。均尊重 `prefers-reduced-motion`。

## 4. 闯关地图页（重写 GameMap）

### 4.1 页面结构（自上而下）

1. **顶部状态条**（吸顶、透明底）：
   - 左：🇨🇳 语文学科标（静态图标）；
   - 🔥 连续学习天数（D4）；
   - 💦/💎 积分余额（实时，取 `profile.points`）；
   - ⭐ 总星数（`map.totalStars`）。
   - 均为「彩色小图标 + 白色粗数字」，点击星数/积分不跳转。
2. **今日额度细条**（D7）：一条胶囊进度，题量与时长合并展示为两段（绿/蓝），右侧文字 `3/20 题 · 6/20 分`；已达上限时整条变橙并显示 🌙 文案，且禁止开局（沿用现有拦截 toast）。
3. **单元橙色横幅**：展示路径当前位置所处单元与课，例如两行：
   - 第 1 行（小字）：`第 1 单元 · 第 1 课`
   - 第 2 行（大字）：`观潮`
   - 语文园地课：`第 1 单元 · 语文园地`；右侧一个白色手册（📒）圆角按钮。
4. **手册弹层**（替代现在的单元手风琴，承担快速浏览/跳转）：
   - 自右侧/底部滑出的目录面板，按 单元 → 课 列出全部 34 个教学单元；
   - 每行显示：课序与课名、该课累计星数、状态图标（✅ 已完成 / ▶ 进行中 / 🔒 未解锁）；
   - 点击已解锁或已完成的课：关闭弹层并让路径**平滑滚动定位**到该课第一个节点；
   - 点击锁定的课：轻提示"先通过前面的内容吧"；
   - 单元为分组标题（第 X 单元 + 单元总星数），不可点。
5. **之字形节点路径**（核心，见 4.2）。
6. 底部仍为三 Tab 栏（闯关 / 商城 / 我的），按深色风格重绘为悬浮彩色图标样式；当前 Tab 高亮。

### 4.2 节点路径规则

- 数据仍取现有 `GET /child/map` 的三级树，前端**拍平**为路径元素序列，后端接口结构不变：
  - `unit-banner`：每单元 1 个（顶部那条橙色横幅吸顶随滚动更新内容，而不是每个单元渲染一条长横幅；路径中单元开始处放一个小型单元标记 `第X单元`）；
  - `lesson-divider`：每课开始前一条课名分隔条（样式同截图"谈论衣物及价格"：左右横线 + 中间课名；语文园地显示 🌸 语文园地；第一课前不渲染分隔条，由横幅承载）；
  - `level-node`：该课下每个关卡 1 个圆形节点；
  - `unit-trophy`：每单元最后一关渲染为**奖杯/宝箱特殊节点**（金色宝箱图标），替代普通圆形，通关后宝箱呈开启态。
- **横向摆位**：节点在容器内按固定模式左右摆动，如 `[中, 左, 中, 右]` 循环（横向位置约 50% / 26% / 50% / 74%），节点后方用 SVG 绘制穿过各节点中心的**弯曲虚线**；课分隔条与单元节点不参与摆动（占满宽度）。
- **节点视觉三态**：
  - 已通关 `PASSED`：金色节点 + 白色 ⭐（⭐⭐⭐ 时显示三星小标？——仅显示 1 颗白星，长按或节点下方小字显示 `x/3`）；节点正下方显示 3 颗小星（获得的着色、未获得灰色），信息与现有星级一致；
  - 当前可挑战 `UNLOCKED`（仅路径上第一个未通关关）：橙色节点、放大 1.18 倍、上下浮动动画；**吉祥物（孩子自己的头像，复用 AvatarFace）站在节点旁边**，气泡文案"继续闯关吧！"；
  - 锁定 `LOCKED`：灰节点 + 灰锁，点击轻提示，不可进入。
- **节点图标变化**（仅装饰，按关卡在课内的序号循环，让画面接近截图的丰富感）：📖 书本 / 🎧 听力式耳机 / ⭐ 星章 / 🎮 游戏柄；语文园地课的节点用 🌸；单元终关固定 🏆 宝箱。
- **初始定位**：进入页面后路径自动滚动，使当前关（`map.currentLevelId`）位于屏幕中部偏下；全部通关时定位到最后一个宝箱。
- 已通关节点可重复挑战（沿用现状：只有首次通关发通关奖励），点击直接开局；点击当前关同样开局。
- 开局前仍校验每日限额（达上限点任何可玩节点都给同一条 toast，不跳转）。

### 4.3 与现有交互的对应

- 现有"默认展开当前单元手风琴"→ 改为"滚动定位当前节点 + 横幅显示当前课"。
- 现有单元卡上的"已通关 ✅、单元星数、已通关 x/y 关"→ 收入手册弹层与横幅，路径不再显示统计卡。
- 顶部的退出按钮移除（我的页保留退出入口）。

## 5. 答题页（重写 GamePlay）

### 5.1 页面结构

1. **顶栏**：
   - 左：`✕` 退出按钮 → 弹确认"现在退出，本次作答不会保存哦"（确认回地图；现有未提交本就不写库，规则不变）；
   - 中：**分段式进度条**（总段数 = 首答题数；错题回炉阶段在条尾追加小段，视觉区分复习段）；
   - 右：`⋯` 次要菜单，内含"跳过本题"（沿用"跳过记为答错"语义）。
2. **内容区**（一次只显示一道题，沿用现有 4 个题型组件，换深色卡通风样式）：
   - 题型小标签（单选/判断/填空/排序）+ 知识点标签（有则显示）；
   - 题干大字；
   - SINGLE：纵向大选项卡；JUDGE：两张并排大卡（✓ 对 / ✗ 错）；BLANK：大号输入框；ORDER：上下两行词卡点击排序（交互逻辑不变）。
3. **底部固定操作坞**：
   - 未作答时：满宽灰按钮"检查"（禁用）；
   - 已作答时：绿色厚边按钮"检查"可点；
   - 点击后进入反馈态（见 5.2）。

### 5.2 检查与反馈（D2/D6）

- 点击"检查"调用新接口 `POST /api/child/session/check`，请求 `{ levelId, questionId, userAnswer }`，返回 `{ isCorrect, correctAnswer, analysis }`（判题逻辑复用后端 `QuestionJudge`；**只读，不写 answer_record、不占每日额度、不发分**）。
- 反馈面板自底部滑入：
  - 答对：绿色面板，✓ 图标 + 文案"答对啦！" + 鼓励语随机短句；按钮变绿色"继续"。
  - 答错：红色面板，✕ 图标 + "正确答案：xxx"；若该题有解析且 `showAnalysisImmediately=true`，同屏展示解析；为 false 时解析留到结算页错题回顾（与现状一致）。选择题同时将正确选项标绿、错选标红。
- 点"继续"进入下一题；最后一题首答完成后进入 5.3。
- 网络失败时允许"再试一次"重新检查，不丢作答。

### 5.3 错题回炉（D3）

- 首答阶段记录每题第一次作答的对错（错与跳过均入回炉队列）。
- 全部首答结束：
  - 队列空：直接提交结算。
  - 队列非空：显示过渡小屏"💪 把刚才的错题再做一遍吧（n 题）"，进度条尾部追加复习段；错题逐题重做，仍走"检查"反馈；回炉中答错可再次检查直到该题答对一次，然后继续；全部做对后提交。
- **结算口径**：提交体中每题答案为**首次作答答案**，因此现有后端 `/child/session/submit` 的正确率、星级、连对、积分、每日计数、答题记录逻辑**完全不变**；回炉仅为学习过程，不重复计分、不重复记记录。前端在提交前对回炉题恢复其首答值。
- 首答即全对时无回炉，体验为最短路径。

### 5.4 提交时机与异常

- 仅在整轮（含回炉）结束时调用一次现有 submit 接口；请求体结构不变（`levelId/durationMs/answers[]`，answers 为首答答案，`durationMs` 为含回炉的总时长，每题时长仍按首答耗时统计）。
- 提交成功后按现有逻辑：`showAnalysisImmediately` 已不影响流程（反馈已逐题发生），**统一跳转新版结算页**；原 GamePlay 内的"逐题回顾(review)"阶段取消。
- 提交失败：弹层允许重试提交；退出则本局不保存。

## 8. 后端改动（最小集）

### 8.1 新增接口：单题判题（只读）

- `POST /api/child/session/check`（Child Token）
- 请求：`{ "levelId": 12, "questionId": 345, "userAnswer": "…JSON 字符串，同 submit 口径" }`
- 响应 data：`{ "questionId": 345, "isCorrect": true, "correctAnswer": <结构化值>, "analysis": "…" }`
- 行为：
  - 校验孩子档案启用中；校验题目存在且属于该 level；
  - 判题复用 `QuestionJudge`，BLANK 答案沿用与 submit 相同的 JSON 归一化；
  - **不校验解锁/限额、不写任何表、不产生积分与计数**（只是"对答案"，结算仍只认 submit）。
- 代码落点：`ChildGameController` 加方法；`GameSessionService`（或新轻量 `AnswerCheckService`）加 `check(childId, levelId, questionId, rawAnswer)`；DTO 加到 `ChildDtos`。

### 8.2 连续学习天数（只读，D4）

- `GET /api/child/profile` 响应增加字段 `streakDays`（int）：
